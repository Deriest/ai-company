## 1. Responsibility

The `storage` module provides the **persistence layer** for the AIC Platform, serving as the canonical source of truth for all domain entities. Its specific responsibilities include:

- **Schema Definition**: Declares the complete relational schema using SQLAlchemy 2.x async ORM with `DeclarativeBase` pattern
- **Session Management**: Exports async database session factory and initialization routines shared with backend services
- **Domain Modeling**: Encapsulates business entities across the autonomous engineering platform including:
  - Task lifecycle management (WorkflowState)
  - Worker orchestration (Worker, Lease)
  - Engineering Discovery Engine state tracking
  - Planning and execution pipeline metadata
  - RAG-based knowledge retrieval infrastructure
  - Plugin/skill ecosystem registries
- **Event Ecosystem**: Defines event types (`EventType`) and audit trail entities for system observability

## 2. Design Patterns

### 2.1 Repository Pattern (Implicit)
The module implements repository-style entity modeling without explicit repository classes. Each model class acts as an aggregated root for its domain.

### 2.2 Unit of Work Pattern
The `AsyncSession` from `sqlalchemy.ext.asyncio` serves as the Unit of Work coordinator:
```python
async_session = AsyncSessionLocal
# All modifications are batch-committed within a single session context
```

### 2.3 Factory Pattern
- `async_session()` function creates scoped async session instances
- Helper functions `_utcnow()`, `_uuid()` provide consistent value factories

### 2.4 Table-per-Class Inheritance Strategy
`Base(DeclarativeBase)` serves as the common base for all ORM models. No subclass inheritance is used; flat hierarchy simplifies PostgreSQL migration.

### 2.5 Composition-over-Inheritance
Relationships use SQLAlchemy's `relationship()` with explicit foreign keys rather than Python inheritance hierarchies. Example:
```python
class Task(Base):
    workflow = relationship("WorkflowState", back_populates="task", uselist=False)
```

### 2.6 Enumerated State Machine
All finite-state concepts use Python `Enum` subclasses with string values:
- `TaskStatus` — FSM phases for task lifecycles
- `LeaseStatus` — Worker lease states
- `ApprovalStatus` — Approval workflow states
- `PolicyDecision` — Policy evaluation outcomes

### 2.7 Composite Identifier Pattern
Primary keys use hex-encoded UUIDs generated by `_uuid()`:
```python
id = Column(String, primary_key=True, default=_uuid)
def _uuid() -> str:
    return uuid4().hex  # 32-char hex string
```

### 2.8 Shadow Field Pattern
Legacy compatibility fields coexist with canonical names:
- `Message.message_metadata` property aliases the canonical `meta` column
- `MemoryEntry.project_id` retained alongside new multi-scope design

### 2.9 Event-Carried State Transfer (ECST)
The `Event` model stores all significant state transitions with full context JSON:
```python
class Event(Base):
    type = Column(String(64), nullable=False, index=True)
    actor = Column(String(128), nullable=True)
    target = Column(String(128), nullable=True)
    data = Column(JSON, default=dict)
```

### 2.10 Optimistic Locking via Retry
`lock_retry.py` implements transient conflict resolution:
```python

    # Implements exponential backoff with reapply hook after rollback
```

**Anti-pattern avoided**: The code explicitly rejects worker serialization. SQLite WAL mode concurrency is preserved with retry-only handling of "database is locked" errors.

## 3. Data & Control Flow

### 3.1 Entry Points

#### Database Initialization
```
init_db() → engine.begin() → Base.metadata.create_all()
```
- Called at application startup
- Creates all tables from ORM metadata in SQLite

#### Session Acquisition
```
get_session() → async_session() → yield session
```
- Context-manager pattern via generator function
- Sessions are automatically closed on stack exit

### 3.2 Data Transformation Pipeline

#### Write Path
1. **Command Creation** (external): Domain service constructs SQLAlchemy operations
2. **Transaction Envelope**: `commit_with_lock_retry()` wraps session commits
3. **Conflict Detection**: `OperationalError` with "locked" message triggers rollback/retry
4. **Recovery Hook**: Optional `reapply()` callback restores pending objects post-rollback
5. **Backoff Delay**: `base_delay * attempt` computes exponential delay

#### Read Path
1. **Query Construction**: External consumers build query expressions against model classes
2. **Session Execution**: `session.scalars/select()` executes async queries
3. **Object Hydration**: ORM materialsizes rows into Python entity instances

### 3.3 State Transition Triggers

```mermaid
stateDiagram-v2
    [*] --> CREATED
    CREATED --> INVESTIGATE : phase.advanced
    INVESTIGATE --> PLANNING : phase.advanced
    PLANNING --> APPROVAL : phase.advanced
    APPROVAL --> IMPLEMENTATION : phase.advanced
    IMPLEMENTATION --> VERIFICATION : phase.advanced
    VERIFICATION --> CLOSEOUT : phase.advanced
    CLOSEOUT --> COMPLETED : phase.advanced
    COMPLETED --> [*]
    
    note right: WorkflowState tracks each transition with barrier logic
```

Each transition is persisted to `workflow_states.history` array with timestamps.

### 3.4 Concurrency Control Flow

```
[Parallel Phase Workers]
         |
         v
  asyncio.gather(tasks)
         |
         v
   [Simultaneous Commits]
         |
    ┌────┴────┐
    | LOCKED? |──YES─→ [Rollback + Reapply + Backoff] ─┐
    └─────────┘                                        │
              NO                                      RETRY (max 6)
              │                                       │
              ▼                                       ▼
        [Success Return]                    [Final Commit or Raise]
```

SQLite's single-writer constraint is respected through asynchronous retries rather than explicit locking.

## 6. Migration Considerations

### 6.1 PostgreSQL Readiness
- String-based UUIDs avoid native UUID type differences
- `JSON` columns map to `JSONB` in PostgreSQL
- No SQLite-specific pragmas embedded in models
- Foreign key references are compatible

### 6.2 Known Constraints
- `conversation_id` in `DiscoverySession` is intentionally NOT a foreign key (semantically references task IDs, not conversation IDs)
- `Message.message_metadata` aliases `meta` column to preserve legacy API contracts
- `MemoryEntry.superseded_by` enables memory versioning/compression
