# 00 — Product Constitution

**Product:** AIC-ADE (Agentic Development Environment)
**Identity:** AI Engineering Company
**Repository:** `AI-Company`
**Version:** v2.3.0
**Authority:** Immutable Product Constitution

---

## 1. Fundamental Declarations

1. **AIC-ADE is an AI Engineering Company, not an AI tool.** When a user opens AIC, the perception should be: "I am running a software engineering company where all employees are AI." Not: "I am chatting with an AI."

2. **AIC Runtime is the Operating Core.** The runtime owns project state, task lifecycle, worker orchestration, provider connections, memory, timeline, and workspace files.

3. **Hermes is the Dispatcher, NOT the Runtime.** Hermes is the technical lead and orchestrator. Hermes dispatches work to specialized workers, coordinates handoffs, and manages the pipeline. Hermes does NOT execute low-level coding or testing directly.

4. **Project Runtime is the Root Object.** Every task, conversation, memory item, worker assignment, timeline event, and code artifact is strictly scoped to a Project Runtime. No engineering state exists floating outside a project.

5. **Runtime is the Single Source of Truth.** Conversation history is an interface view. The persisted runtime database, SQLite storage, and workspace file system form the true engineering state.

6. **Workers Execute, Not Just Chat.** Workers use real tools (file read/write, shell, search, explore) to produce actual artifacts. Text-only LLM responses without tool execution are prohibited for engineering tasks.

7. **The Command Center is the Entry Point.** Chat is the unified entry point with intent-based routing. User gives briefs, the AI Company executes. Not the other way around.

---

## 2. Inviolable Product Rules

- **No Fake Data or Fallback Synthetics:** The application must never present mock data, fake progress, or synthetic assistant success when backend execution fails. All errors must be surfaced transparently.
- **No Floating Artifacts:** Every output generated by workers must belong to a tracked task and project workspace.
- **Strict Tier Model Routing:** Model selection is governed by capability tiers (`Thinker`, `Crafter`, `Sprinter`). Fallback routes automatically across tiers.
- **Autonomous Execution with User Governance:** Workers execute autonomously inside the workspace environment. High-impact operations require human approval.
- **Local-First:** All data stays on the host machine. No cloud dependency, no telemetry, no external data leaks.
- **Tool Permissions Enforced:** Workers can only use tools they're authorized for. Prohibited tools are denied. Restricted tools require approval.

## 4. Worker Identity

Every worker has:
- **Name** (e.g., Hermes, Atlas, Hugo)
- **Department** (Leadership, Product, Engineering, Platform)
- **Tier** (Thinker, Crafter, Sprinter)
- **Phase** (which FSM phase they work in)
- **ToolPermissions** (allowed, restricted, prohibited)
- **Skills** (injectable instruction snippets)
- **Anti-patterns** (what they must never do)
- **Escalation policy** (when to escalate to user)

Workers are NOT generic chatbots. They are specialized employees with distinct identities and responsibilities.
